# v0.6 Scalable Evidence Extraction

## Benchmark set role and history

The seven-paper set is the **development set** and is no longer an independent holdout. The final development Gold is human-adjudicated at `data/evidence_benchmarks/gold_v04_development_final/candidate_gold.jsonl`; its decisions are recorded in `human_decision_log.jsonl`. Development Gold must not be used as an independent final performance estimate. The historical iteration-1 result remains `v06_strict_lexical_v1` (field micro-F1 0.599, finding precision 0.756, recall 0.939, gate FAIL); source Gold, frozen benchmark reports, iteration-1 worker responses, schema, validator, and contract remain unchanged.

The seven development identities are in `data/evidence_benchmarks/gold_v04/identities.json`. The versioned candidate chain ends in a human-adjudicated development Gold; it is not an independent performance set. Prompt iteration 2 may use only these seven development papers, Evidence Field Contract v1, and development error analysis. The separate 20-paper holdout remains frozen and untouched; do not read its abstracts, Evidence, or responses during prompt development.

See [Evidence Field Contract v1](evidence_field_contract_v1.md) for the adjudicated operational definitions. v0.4 schema structure and strict v1 metrics remain unchanged.

`HOLDOUT_FROZEN_BEFORE_PROMPT_ITERATION_2 = true`

v0.6 uses the Evidence Matrix v0.4 content schema, with a separate pipeline version. Production WoS and enriched JSONL files remain read-only. Evidence is stored in a separate 276-identity sidecar.

## Stages

1. `batch_prepare.py` makes canonical-order requests using the existing payload whitelist. It cuts batches by both record count (default 8) and abstract characters (default 60,000); a single longer abstract occupies its own batch. Valid responses can be resumed. Prompt or schema hash changes invalidate old responses.
2. Codex processes one batch in an isolated context under the [worker protocol](codex_evidence_worker.md). No API key, network, gold answer, previous evidence, or research profile is available to the worker.
3. `batch_ingest.py` validates identity, schema, abstract grounding, offsets, and anchors; records protocol provenance; applies contextual audit flags; and keeps every canonical identity in the sidecar. Missing abstracts become `needs_fulltext`, the three unresolved abstract conflicts become `needs_manual_resolution`, historical reviewed gold rows stay marked `gold_reviewed`, and unprocessed abstract records remain `queued`.
4. `benchmark.py` compares blind worker results with the human-adjudicated seven-paper development Gold using the preserved strict metric and calibrated metric. All such scores are development diagnostics, not independent performance. The historical fixed quality gate is not permission to access the frozen holdout or start a pilot.
5. Only after an independently reviewed pilot can a later run prepare the remaining full-corpus queue. Full extraction is not part of this stage.

## Commands

Prepare the seven blind requests. Keep the identity selector and gold data outside the worker batch directory:

```bash
python scripts/evidence/batch_prepare.py \
  data/processed/saline_paddy_v056_full_enriched_20261003.jsonl \
  --output-dir data/evidence_batches/v06_gold_blind_20261004 \
  --uids-file data/evidence_benchmarks/gold_v04/identities.json
```

After the independent worker writes responses:

```bash
python scripts/evidence/benchmark.py \
  data/evidence_batches/v06_gold_blind_20261004 \
  --canonical-input data/processed/saline_paddy_v056_full_enriched_20261003.jsonl \
  --gold-evidence data/evidence/20261003_192326_169425_evidence_57015bbc_evidence.jsonl
```

Build or resume an all-identity sidecar after responses are reviewed:

```bash
python scripts/evidence/batch_ingest.py data/evidence_batches/v06_gold_blind_20261004 \
  --canonical-input data/processed/saline_paddy_v056_full_enriched_20261003.jsonl \
  --unresolved-file data/reports/20261003_235840_787376_abstracts_94203196_unresolved_abstracts.json \
  --gold-evidence-file data/evidence/20261003_192326_169425_evidence_57015bbc_evidence.jsonl \
  --conflict-doi 10.1039/d4em00698d --conflict-doi 10.1002/ldr.5442 \
  --conflict-doi 10.1007/s42773-026-00619-7 \
  --output data/evidence/v06_full_corpus_sidecar_20261004.jsonl
```

`screening_profile.py` runs only after validated extraction. The profile owns formal eligibility; the extraction worker does not.

## Quality gate

For prompt development, prioritize 100% schema, grounding, identifier, and response-contract validity (abstract records remain `maybe`, inference arrays remain empty); zero unsupported facts/findings, invalid offsets, and orphan anchors; improved finding precision and experimental-scale recall; reduced salinity-context false positives; and no new severe category errors. Development metrics guide bounded prompt iteration only and must not be described as independent performance. Do not tune to an arbitrary F1 target or start a pilot from this development set. Risk flags such as short support, review language, recommendations, and association-as-treatment risk do not weaken the strict validator.

## Human-adjudicated development Gold

- `data/evidence_benchmarks/gold_v04_development_final/` is a new derivative built from the v061b candidate plus all 11 user decisions. The original Gold, v061a, and v061b remain unchanged.
- The 11 decisions have `human_reviewed=true`, `human_decision=ACCEPT|REJECT`, `approved_by=human`, and `approved_at` in `human_decision_log.jsonl`.
- The final development Gold passed JSON Schema, EvidenceValidator grounding, offset, orphan-anchor, and identity validation. Its manifest records the validation summary and source hashes.
- The 20-paper holdout remains frozen and untouched. It is reserved for a separately authorized evaluation; Prompt iteration 2 and development tuning must not inspect holdout abstracts, Evidence, or responses.

All `data/` outputs remain ignored. Tests and benchmark scoring are offline; no OpenAI API key is required.
