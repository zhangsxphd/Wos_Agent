# v0.7 深度审查与可靠性修复（2026-10-27）

## 范围和结论

基于 `v0.7-field-reliability` 的 `bb3f89f23631c679e5d4251171affcf0e6070f12`，在本地分支 `codex/v07-reliability-audit` 工作。审查了检索归一化与合并、摘要 Provider、筛选、全文获取与解析、数据质量、Evidence Worker、Gold 和冻结评估入口、测试和 CI；属于基于风险的审查，不表示逐行审完仓库。原始 WoS 响应、文献池、PDF、历史 Gold 和冻结文件未被修改；新质量报告另存本地忽略目录。本轮没有重新进行模型实验，也没有证明系统具备稳定的大规模科研证据提取能力。

## 已经存在的保护和先前判断的修正

不能把所有传闻都当成缺陷：S2 长 `Retry-After` 原先已有 Provider 冷却设计，本次补足批处理验证而不是宣称此前没有限流；检索本身记录 query、页数、来源及是否截断；Worker 已有请求/响应哈希绑定和逐文件校验；`final_evaluation.py` 已要求新 holdout 的参考答案和项目负责人审核、检查已知 Dev40 重叠。因此“没有任何来源记录或任何审核门槛”并不符合代码。上述措施只证明保护存在，不证明模型事实准确、全部 holdout 相互独立或所有并发写入安全。

历史冻结的 prompt、contract、schema、两个 metrics 和 validator 的六个 SHA256 本轮 `verify_frozen()` 均通过。`data/evidence_benchmarks/v07_dev40_gold_final/gold_freeze_manifest.json` 明确记录 `ai_assisted_development_reference`、`human_review_complete=false`、27 行选定人工裁决，以及并非每条均独立人工标注。不能把开发 Gold 或模型间一致当成人工金标准。历史 holdout 注册文件缺失，新 holdout 只能检查与已知开发集重叠，旧 holdout 的重叠状态仍是未知。

历史 Dev40 报告的 v1 字段 F1 0.7817、v2 字段 F1 0.8564、findings v1 F1 0.9532、methods v2 F1 0.5797 均为先前开发指标，未在本轮重算，也不是独立外部准确率。`docs/v07_dev40_final_selection.md` 显示 methods 从 baseline 0.6842、I1 0.6197 降到 I2 0.5797；字段范围、标注一致性和提示词遗漏是需要逐条对照错例的假设，现存缺失历史响应不足以确认原因。

## 尚未解决及其顺序

1. **高优先级：TEI 与全文证据准入。** TEI 下载没有像 PDF 一样在来源文档中独立确认 DOI；历史 `available` 清单也未普遍通过新增检查。先从 TEI header 提取身份并设置独立 review 状态，再约束证据构建入口、补充真实多版本样本；不要以 `available` 推断所有格式均可信。
2. **高优先级：参考答案与独立评价。** 找回 19 项历史材料或承认无法复原；用不与已知开发集重叠的新样本建立真正独立的人审参考，记录双人分歧和裁决；分别测试方法、处理、数值单位、否定、不显著、相关/因果和定位。原历史 holdout 重叠未知必须明示。新指标需独立版本、先固定方案再评测，不能改历史 v2。
3. **高优先级：缓存与 URL 边界。** S2 的隔离修复不等于所有 Provider 均具备同样恢复能力；Crossref/OpenAlex 的损坏缓存、刷新历史和原子并发写入仍需增强。OpenAlex 老批量负缓存无验证哈希需显式刷新。URL 当前检查字面私网地址，未防止公开域名解析或重定向至私网、DNS 重绑定；不得在对不可信 URL 开放的服务中视为完整 SSRF 防护。
4. **数据身份与科研内容：** 题名+年份后备仍自动合并，可能误合并同名论文；同 DOI 合并的不同非空字段尚无完整差异记录；勘误、撤稿、版本关系尚待外部来源核实。逐篇检查 32 条版面和 14 份摘要，核对两条日期，并在新输出版本保留人工决定。必要时继续通过用户已授权浏览器获取全文。
5. **工程边界：** 新 `safe_url` 不涵盖所有未知签名参数；XML/PDF 的恶意输入、论文中的提示注入、Worker 响应丢失/重试、权限与各种并发环境需专项威胁建模和测试。依赖锁可用于 Python 3.12 CI，尚未实测 Windows、新机器或不支持硬链接的文件系统。

## 下一版本建议

优先开发三项：一是 Provider 缓存与全文身份的统一证据状态和可恢复隔离，先封住 TEI/缓存/URL 边界；二是有人工裁决、版本化参考答案和独立 holdout 的字段级评估；三是研究问题拆解、可审查检索策略、溯源筛选与引用追踪，先服务人工决策。之后才考虑跨论文证据比较和创新性审查：必须提供相近研究、差异与检索缺口，不能将未检索到等同无人研究。

复用现有成熟工具：HTTP 客户端和官方 API、pypdf/GROBID 提取、Crossref/OpenAlex/PubMed 公开元数据，以及版本控制和 CI；任何工具的解析输出都需身份和证据验证。暂缓自建数据库、向量库、复杂前端和多智能体框架，也不应在缺少独立人审样本时花费大量调用争取更高单一 F1。LLM 事实提取和研究启发应保持不同结构，推测不得回写论文事实。
