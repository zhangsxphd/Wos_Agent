**开始读取新文献：** 不需要先写 manifest；从本地 PDF/XLSX 提取带哈希、页码/单元格的研究设计、处理、对照、指标与单位候选。候选片段是程序输出，可能误识别，必须人工确认。

```sh
python research_projects/awd_n2o_mvp/run.py --discover path/to/article.pdf path/to/table.xlsx --out outputs/intake
```

**复现本轮批量综合：** 在仓库根目录、Python 安装 `pdfplumber` 后运行；公开原文若本地不存在则由清单中合法公开来源下载并校验哈希：

```sh
python research_projects/awd_n2o_mvp/run.py --manifest research_projects/awd_n2o_mvp/v092/manifest.json --corrections research_projects/awd_n2o_mvp/v092/corrections.json --sources outputs/v092/sources --out outputs/v092/run
```

两阶段输出：[程序候选与位置](intake_candidates.json)、[规范化证据](normalized_evidence.json)、[综合](synthesis.json)、[自动科研报告](analysis.md)、[运行和修改记录](run_log.json)。候选读取成功不自动代表原文位置确认；清单的状态声明不再使结果变成已核查或 Gold。当前四条均是程序定位、待独立核查的 Candidate。

**实际人工介入与错误：** 先用程序片段定位并阅读论文、设计和表格，再手工指定两篇的 PDF 页、处理组、指标与列、年份/单位匹配模式。秘鲁 PDF 实际叠加两套文字，未经筛选的字符会重复、部分列混排；助手视觉核查后通过 [corrections.json](corrections.json) 指定字体层，程序再从原文件取数。此前提取接口按捕获顺序理解处理组，两个新表均先列 CF 后列 AWD；现以命名捕获明确对应顺序并保留原文片段。上述是助手介入，不是独立人工认证；运行日志保存修改前后、原因与操作者，没有人工改写结果数值。

原 N₂O 和 N₂O-N 单位已按 44/28 统一时，报告不再把原始单位差异说成仍未解决的量纲障碍；但不同设计、对照、施肥、观测期间及伪重复仍使条件性比较不足。CO₂ 当量无法按 44/28 换成 N₂O，保持未知。一次批量运行产生 4 篇记录、4 个比较、6 组可比性判断、0 个跨研究共同发现；不得将多次配对或同方向数值当作独立发现。
