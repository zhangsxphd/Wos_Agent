# v0.5.5 Elsevier Entitled Full-Text Fallback

v0.5.5 adds an entitlement-aware publisher API fallback without changing the v0.5 OA resolver.

## Acquisition order

1. Existing OpenAlex OA resolver.
2. Elsevier Article Retrieval API by exact DOI, using `view=FULL`.
3. If neither route returns validated full text, keep the record unavailable/error with per-route provenance.

The Elsevier route is only attempted when `ELSEVIER_API_KEY` is configured locally. An optional `ELSEVIER_INSTTOKEN` is supported for institutions that explicitly provide one. Otherwise Elsevier may resolve institutional entitlement from the caller IP/network.

## Local credentials

Keep credentials only in the local `.env` file:

~~~text
ELSEVIER_API_KEY=
ELSEVIER_INSTTOKEN=
~~~

The key is sent only in the `X-ELS-APIKey` request header. The optional institution token is sent only in `X-ELS-Insttoken`. Neither value is placed in the request URL, cache, sidecars, manifests, logs, fixtures, or repository files.

## Article Retrieval request

The client uses:

~~~text
GET https://api.elsevier.com/content/article/doi/<DOI>
Accept: text/xml
X-ELS-APIKey: <local secret>
view=FULL
~~~

`view=FULL` is intentional: the resolver requires a full-text response and rejects metadata/abstract-only XML.

## Usage

From the repository root:

~~~bash
source .venv/bin/activate
python scripts/resolve_entitled_fulltexts.py   data/processed/<canonical>.jsonl   --output data/fulltext/runs/<new-sidecar>.jsonl
~~~

The command preserves the canonical input byte-for-byte and writes a separate sidecar plus manifest.

## Output provenance

A successful Elsevier result records:

- DOI and WoS UID
- acquisition route: `elsevier_api`
- source URL without credentials
- format: `elsevier_xml`
- entitlement marker: `FULL`
- SHA256 of the raw XML
- raw and parsed sidecar paths
- router attempts
- HTTP/provider statistics without secrets

Elsevier XML is parsed into the same section/paragraph shape used by the v0.5 full-text evidence layer, with stable paragraph IDs and section scopes.
The parsed title is checked against the WoS title; a DOI returned by Elsevier is checked against the requested DOI. External DTD declarations are stripped before parsing, and XML with an internal DTD/entity declaration is rejected. Abstract-only `para` nodes are not treated as article body text.

Validated successful responses are cached by normalized DOI. Cache replay verifies the raw XML SHA256 and reparses the XML to check that parsed JSON is unchanged. Errors and access denials are never written as negative full-text cache entries. The run manifest includes HTTP request counts, cache hits, Elsevier rate-limit headers, per-record HTTP status, parser status, and body paragraph count; credentials are excluded.

## Failure semantics

- 404 -> `elsevier_not_found`
- 401/403 -> `elsevier_access_denied`
- 429 -> bounded retry, then `elsevier_rate_limited`
- 5xx/network -> bounded retry, then transient error
- 200 without validated article body -> rejected as `elsevier_fulltext_body_missing`

The resolver never treats a failed publisher request as evidence that the paper itself does not exist.

## Safety and policy boundary

This integration uses the documented Elsevier Article Retrieval API for non-commercial research access. It does not automate ScienceDirect browser scraping, bypass paywalls, defeat CAPTCHA/MFA, or use shadow-library sources.

Run the offline suite after changes:

~~~bash
python tests/run_offline.py -v
~~~
