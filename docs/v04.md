# v0.4 Evidence Matrix

本阶段仅在已有 enriched JSONL 上增加独立证据层，未修改 WoS 检索、合并去重或摘要补全核心。默认完全离线，Semantic Scholar 不调用，OpenAIExtractor 只是预留接口。

## 文件与边界

- `schemas/evidence_matrix.schema.json`：Draft 2020-12 Schema，包含 screening、evidence、独立 inference、completeness。
- `scripts/extractors/base.py`：统一 `extract(record)` 接口、白名单 payload、内容哈希、空记录。
- `scripts/extractors/schema_validator.py`：Schema、原文片段、字符位置、标识一致性、完整度和推理锚点校验。
- `scripts/extractors/manual.py`：读取人工审核的 `<payload_key>.json`。
- `scripts/extractors/cached.py`：经过校验的原始提取响应缓存；输入、Schema、prompt 任一变化都使旧缓存失效。
- `scripts/extractors/openai.py`：未配置时返回固定错误，不创建客户端、不读取模型 Key、不联网。
- `scripts/build_evidence_matrix.py`：准备人工输入、提取、留存 raw response、标准化、生成独立 JSONL 和 manifest。
- `scripts/evidence_export.py`：按 uid/doi/title 精确连接 canonical 和 Evidence；少行、多行、重复身份均拒绝导出。
- `prompts/evidence_extraction.md` / `prompts/research_inference.md`：原文提取与第二阶段推理分别使用不同 prompt。
- `tests/test_v04.py`：36 项新增离线测试。

`requirements.txt` 新增 jsonschema。Schema 校验使用本地文件，不解析远程引用；实现依据 [jsonschema 官方验证文档](https://python-jsonschema.readthedocs.io/en/stable/validate/)。Excel 仍使用原来的 Artifact Tool 运行时。

## 人工提取流程

```bash
cd ~/wos-research-agent
source .venv/bin/activate
pip install -r requirements.txt

python scripts/build_evidence_matrix.py data/processed/my_enriched.jsonl --prepare-only
```

命令显示新建的 `data/raw/evidence/<run_id>/`。`requests/` 只包含 uid、doi、title、journal、year、authors、keywords、document_types、abstract，不包含用户个人背景、provider HTTP 响应或 API Key。`templates/` 是同名空响应模板。将模板复制到单独的人工审核目录，按照原始摘要填写，保持哈希文件名不变。

```bash
python scripts/build_evidence_matrix.py data/processed/my_enriched.jsonl \
  --manual-dir data/manual/my_reviewed_responses
```

默认生成 `data/evidence/<run_id>_evidence.jsonl` 和同名 manifest；人工响应原样复制到该次 `data/raw/evidence/<run_id>/responses/`，canonical JSONL 不覆盖。

```bash
# 重放已经校验的提取缓存，完全离线
python scripts/build_evidence_matrix.py data/processed/my_enriched.jsonl --cache-only

# 重新读取已审核的人工响应；已有 raw 留档保留
python scripts/build_evidence_matrix.py data/processed/my_enriched.jsonl \
  --manual-dir data/manual/my_reviewed_responses --refresh

python scripts/export_records.py data/processed/my_enriched.jsonl \
  --output-prefix data/exports/my_evidence --include-abstracts \
  --evidence data/evidence/ACTUAL_RUN_ID_evidence.jsonl

python tests/run_offline.py
```

所有输出采用新路径；没有指定 `--evidence` 时保留既有导出行为。CSV 继续导出 canonical 书目/摘要字段，Evidence JSONL 是证据层的机器可读格式，XLSX 新增 Evidence 和 Research_Inference 分表。超过 Excel 单元格长度限制时拒绝 XLSX 导出，不截短证据文本。

## 支持文本与推理

v0.4 的非空实验事实采用保守约束：必须出现在摘要中。`evidence_support` 使用 JSON Pointer，逐个保存事实的 `source`、`evidence_text`、`start`、`end`。位置采用原始 Python 字符串的零基字符索引，区间为 `[start, end)`，不是字节位置。

finding 的 evidence_text 必须是原摘要的精确子串；claim 也必须是该片段中的原文子串。数值、单位、否定、条件、模型预测与综述语境保留原词，不改写成新的结论。实验 scale 使用有限枚举和明确原文支持。Schema 预留 metadata source，但本轮 finding 及实验事实仍强制使用 abstract，避免将题名、作者地址或关键词当成实验细节。

推理单独使用如下结构，不能混入 evidence：

```json
{
  "statement": "需要进一步核实该结果在其他环境中的适用性。",
  "kind": "inference",
  "evidence_anchors": ["/evidence/findings/0"]
}
```

锚点必须指向已有、非空、受到原文支持的事实或 finding；标题、空字段和不存在的数组项都拒绝。没有摘要时所有实验事实和推理保持为空，screening 固定为 needs_fulltext，不调用 extractor。

校验器验证字面来源与结构，不能自动证明某个原句在语义上属于处理、机制或限制。人工审核仍需区分综述转述、背景方法、实际处理、观察关联和模型情景；源句存在本身不证明因果。第一轮 inference 全部为空，未生成研究空白或创新性判断。

单条响应不合格时保留其他已完成记录；安全的原始响应仍留档以供审核，该条输出 needs_fulltext 和固定 rejected 状态。包含已知 Key 的响应不保存、不缓存、不回显。若有 rejected，CLI 退出码为 1，成功记录仍可复查。

## 完整度与 screening

`has_abstract`、`has_treatment`、`has_methods`、`has_findings` 只反映本次结构化结果是否有对应信息。四者都有为 high；有摘要、findings 且至少有 treatment 或 methods 为 medium；其余为 low。任何一项缺失或 screening 为 needs_fulltext，completeness.needs_fulltext 为 true。

screening.needs_fulltext 与 completeness.needs_fulltext 是不同统计。综述、观测或模型研究可能没有实际施加的 treatment，因此完整度较低也不表示论文质量低。没有给出正式纳入标准时，有摘要条目保持 maybe；本程序不自动排除论文。空 limitations 表示本次摘要未提取到明确限制，不表示研究没有限制。
